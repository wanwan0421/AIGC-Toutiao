记录日期：2026-10-24。作者尚未提供旅游、研究生生活各 10 份未参与建档的新素材，也尚未完成盲选。本记录区分已经验证的自动化结果与等待素材的实测项目；目前不能宣称达到 14/20 的效果目标。

## 盲测操作

1. 在项目根目录执行 `npm.cmd run eval:writing-style -w @aicp/api -- template ../../tmp/writing-style-cases.json`，填入 20 题完整的新经历、约束和要求。`brief` 应包含作者准备用于判断两版文章的全部新事实。每个题目填入无风格、有主题风格两次生成的 `AiJob.id`，并填写对应主题的固定 `styleVersionId` 与 `topicKey`。
2. 先固定同一代码版本、模型部署、提示词版本、思考模式和图片配置。每题复制相同输入与素材到两个**独立草稿**，一份选择“不使用写作风格”，一份选择指定主题风格；不要在两次生成之间修改素材、档案版本或配置。记录失败、重试和没有成功入库的任务，不能挑选成功样本替换题目。
3. 在生成并入库后、人工编辑前执行 `npm.cmd run eval:writing-style -w @aicp/api -- prepare ../../tmp/writing-style-cases.json ../../tmp/writing-style-run-01`。脚本只读数据库，检查 20 题分布、40 个不同任务与草稿、同一作者、相同冻结输入、同一主题风格版本、相同模型/提示词/思考配置、各阶段成功日志和当前入库文章 25/1000 限制。检查失败时先修正试验过程，不能跳过检查。
4. 只给作者 `tmp/writing-style-run-01/blind-cards.md` 与 `ratings.json`，保留 `answer-key.json` 不公开。A/B 顺序逐题随机。作者对每版填写风格相似度、结构吻合、关键新事实覆盖（1–5 分）、旧文事实误用数量，以及实际修改分钟数与修改字符数；每题选择 A、B 或平局，并记录原因。评分前不要揭盲。
5. 完成评分后执行 `npm.cmd run eval:writing-style -w @aicp/api -- report ../../tmp/writing-style-run-01 ../../tmp/writing-style-run-01/report.json`。报告给出盲选数、两组评分/编辑量/总耗时/各阶段首 Token/重试/Token/价格快照费用的均值、缺失数据覆盖率和失败样本。仅在 20 题偏好和全部指标都填写后标记 `complete=true`；14/20 是首轮目标，不是统计证明。若改提示词或档案，另取新的保留样本复测。

`tmp/` 已被 Git 忽略。盲测稿、答卷和答案键可能含作者经历，留在本机；如需共享，仅发送给授权评测者。费用是调用时保存的公开标价估算，不是账单；未记录 Token 或价格的调用显示为缺失，不填零。对照工具能从调用日志核对模型、提示词版本、思考模式与 API 类型；温度和采样配置没有独立日志字段，因此必须保持同一部署和提示词版本，并在评测记录中注明版本。生成图片本身具有随机性，评价时记录明显的图片质量差异。

## 部署、回滚与演示

部署前备份数据库，记录代码版本、模型部署、提示词版本和环境开关；先应用现有加法迁移，再部署共享包、API、worker、Web 同一版本，核对 `prisma migrate status` 和编译结果。保持旧 Job 解析兼容，历史文章不批量改写。部署后按矩阵验证一位作者的真实路径：选旧文首建 → 编辑并确认候选 → 在编辑器选择主题风格生成 → 发布 → 纳入新样本并产生候选更新 → 再次确认后生成。

若新入口或 worker 路由异常，先停止继续提交新的写作风格任务，将应用版本回退到已验证版本；保留加法表、档案、已写入的来源与任务记录，采用前向兼容修复，不删除用户内容或强行回滚数据库。恢复服务后核对排队任务的冻结素材/档案版本，再决定继续或取消。正式部署和回滚操作尚未执行，本段是操作顺序。
